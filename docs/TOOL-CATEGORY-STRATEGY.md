# Category and cluster strategy

The launch navigation has four artifact-based families. Tools are categorized by what a person works on, not by dozens of verbs. Tags aid search but never generate indexable archive pages.

All launch families have conditional Medium AdSense suitability: benign user tasks with original explanation are plausible inventory, but no family label assures acceptance. Tool pages remain ad-free by project privacy design. Data requirements for every launch tool are local input plus bundled static code; no remote data feeds.

## Hubs

| Hub | Navigation label | Core user promise | Editorial connections |
|---|---|---|---|
| /tools/text/ | Text & Lists | Clean, count and compare pasted material | Copied-text cleanup, Unicode counts, comparison semantics |
| /tools/data/ | Data & Tables | Inspect, clean and convert small exports | CSV import diagnosis, duplicate keys, nested JSON |
| /tools/image/ | Images | Prepare supported raster images for reuse | Pixels vs bytes, upload limits, crop vs resize |
| /tools/web/ | Web & Publishing | Prepare links, encoded text and color values | URL behavior, color contrast |

Each has enough launch tools to justify a real hub. Show a concise introduction, task groups with descriptions, practical starting paths, applicable guides and two related families. Do not duplicate the directory verbatim. “Popular” requires measured evidence; start with “Start here” curated tools. Expansion must deepen workflow value, not fill arbitrary category quotas.

## Category promotion rule

A new family needs at least three release-ready distinct tools, a documented common workflow, original supporting material and a maintenance owner. This is an internal UX rule, not a Google requirement. Deferred family pages do not exist publicly. Reconsider tools using user feedback, measured discovery and implementation capacity; no fixed keyword-volume threshold.
