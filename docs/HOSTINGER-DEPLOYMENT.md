# Hostinger static deployment

This project builds static HTML and browser JavaScript. For standard Hostinger web hosting, upload the **contents** of `dist/` into this domain's `public_html/`, including the hidden `.htaccess`. Do not upload the source repository, dependencies, tests or private environment files. No Node server is needed for this hosting mode. Back up existing hosting files before replacing them. A Hostinger VPS or Website Builder product needs a different deployment workflow; this configuration targets Apache/LiteSpeed web hosting.

1. Connect the domain in hPanel and provision SSL covering apex and www. Confirm the certificate is active before enabling redirects. Hostinger provides an [HTTPS control](https://www.hostinger.com/support/1583201-how-to-enable-or-disable-https-for-your-website-at-hostinger/).
2. Supply factual `SITE_OPERATOR`, `CONTACT_EMAIL`, `HOST_NAME=Hostinger`, `HOST_PRIVACY_URL` and `LOG_RETENTION` build settings. Confirm the last two against your actual hosting/account practices. Set `GOOGLE_SITE_VERIFICATION` if using Search Console's HTML tag method. Do not put invented values into the release guard.
3. Run `RELEASE=1` with `npm.cmd run build` using the shell's environment-variable syntax. Run the tests and audits listed in README. Upload the built files. The build generates `.htaccess` for HTTPS/apex redirects, known-route normalization, true 404 handling, security headers, compression and cache revalidation. Hostinger [supports .htaccess](https://www.hostinger.com/support/1583307-how-to-create-an-htaccess-file-at-hostinger/). These rules have not yet been executed on your hosting account.
4. Use full HTTPS from any CDN to the origin; an HTTP-only origin connection behind a TLS proxy can create redirect loops. Check this before enabling a CDN. Do not combine conflicting redirect rules. Purge hosting/CDN caches after deployment, especially on the first transition to this cache policy.
5. Check `http://utilitypilot.online/`, `https://www.utilitypilot.online/`, `/tools/text/word-counter`, `/tools/text/word-counter/index.html`, `/TOOLS/TEXT/WORD-COUNTER/`, `/tools/?q=test`, an unknown URL, `/404/`, `/robots.txt` and `/sitemap.xml`. Known pages should reach the correct HTTPS/apex/slash URL; unknown pages must return HTTP 404. Test actual headers and decoded assets, not just the visual page.
6. Verify ownership in the owner's Search Console account, then submit the sitemap. Run PageSpeed Insights against public home, category, guide and tool URLs on mobile and desktop. Inspect image, CSV and long-text workflows in a browser too.

The local Node server's `ENFORCE_HTTPS` and `TRUST_PROXY` settings do not apply to Hostinger static uploads. The generated `.htaccess` is the host-specific replacement for the portable `_headers` file. Live certificate, redirect, compression and ownership-verification checks remain pending access/deployment; no public launch was performed by this task.
